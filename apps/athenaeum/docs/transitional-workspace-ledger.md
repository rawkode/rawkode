# Transitional Workspace Ledger

`WorkspaceDurableObject.createNode` is the only public mutation currently routed through the workspace-local ledger. It derives principal (`authenticated email` or canonical `anonymous`), build capability and governed/ungoverned policy on the server after the existing role gate. The persisted immutable command uses `athenaeum.workspace-ledger.v1`; its current `create-node-title-compat.v1` message, `Create node to record <normalized title>.`, is a deterministic server-derived compatibility placeholder because the public caller supplies no rationale. It is not a claim about caller intent. A future full command contract must require caller/job rationale; explicit-ID replay remains immutable and deterministic under the compatibility derivation.

An explicit client node ID supplies the only compatible cross-call replay identity. Calls without one receive a fresh outer-RPC identity and are not represented as cross-client retries. The command is validated against the exported `LedgerCommand` Effect Schema before insertion; the node KV projection, SQL/FTS read model, sync-feed entry, outbox intent and receipt are written inside one synchronous DO-storage transaction. The routing inventory catalogues every public Workspace mutation RPC (including `mintAppRunCredential`) plus the App HTTP mutation path; all except `createNode` are explicit direct bypasses. This is not an authority-complete ledger.
