# Native core screen audit

2026-09-13. Read-only audit of current SwiftUI source. No new runtime screenshots or accessibility session were taken for this audit; the parent is fixing task creation in the daily editor first. Previous simulator screenshots do not establish the current render. Apply the existing SwiftUI UI-patterns and macOS patterns guidance. Keep the accepted day timeline, calendar colors, sidebar, Today action, and note pull-up; do not introduce another navigation system.

## Order of work

1. Prove that a task created inside the daily note becomes the same task in the task workspace, survives reload, and can be completed from either surface. This is the release blocker; screen polish must not displace it.
2. Repair missing destinations and misleading loading/save/conflict states.
3. Remove duplicate navigation and implementation explanations; use existing native forms, lists, toolbar actions, sheets, search, and date formatting.
4. Validate each screen in Dawn/Dark, at accessibility text sizes, with VoiceOver, and with offline/empty/error data. A build does not validate these interactions.

## Elements that earn their place

- The week strip selects a day; all-day separation, calendar colors, and event detail preserve scheduling meaning.
- The Today control recentres on the current time; the note preview opens the daily note and keeps the accepted swipe-up affordance.
- The sidebar provides one stable route to secondary workspaces. Keep a visible menu button in addition to the gesture.
- Task completion, due date, priority, title, revision-conflict state, and pending status affect a user's next action. Preserve them without exposing implementation vocabulary.
- Save errors, account identity, and offline status are necessary when accurate and scoped to the current operation.
- Local-note ownership must remain explicit until actual migration exists.

## Verification matrix after the task-creation blocker

- **Daily note:** create a task from the note; reload; see it in Tasks; complete from each surface; verify exactly one graph task and consistent checked state. Repeat offline only if that path is supported.
- **Phone home:** Dawn/Dark; day selection; Today recenter; all-day and overlapping events; calendar colors; sidebar button/swipe; note tap/pull-up; large text.
- **iPad workspace:** phone-equivalent Voice, meeting capture, tasks and note access at regular/compact widths; selection continuity.
- **Tasks:** new task with keyboard focus; date/priority edit; search across the promised scope; complete/reopen; delayed response; no connection; restart with pending edits; revision conflict resolution; no-account onboarding.
- **Captures:** empty and populated creation; retained draft on close; no-result search; canonical add-to-note without duplicates; failure retains source text.
- **Settings:** identify active account; automatic successful sign-in; actionable failure; sign-out; appearance persists; detailed storage copy stays out of routine account flow.
- **Device notes:** explicit local ownership, date changes preserve edits, local save errors are truthful, share works, no silent migration.

This audit supplies implementation order and acceptance criteria; it does not claim those improvements are built, deployed, or runtime-verified.

## Content hierarchy follow-up — 13 September 2026

Pending task edits now occupy their normal task rows with an inline sync state. The collection picker sits directly beneath navigation, with system body typography and primary text contrast. A normalized identity projection prevents a refreshed canonical task from duplicating an unacknowledged local create. Conflicts retain remote values, reveal local changes, remain visible across collections, and match either title in search. Reapplication remains deferred.

Meeting Notes uses the full writing area beneath the fixed native segmented picker. Recording preparation belongs to Transcript; Notes routes to it through Set up recording. Active recording status and errors remain visible when relevant, and finished meetings omit recording controls. Existing recorder ownership, draft persistence, and microphone activation rules are unchanged.

Verification: Mac build passed; the three targeted iPhone Simulator UI journeys passed (offline task save/relaunch, Dark tasks, meeting note switching/save/relaunch and awareness gating). A production-source regression executable covers lost create replies, acknowledgement, updates and conflicts and runs from `apple/script/check.sh`. Independent review found no remaining blockers. Actual XCTest screenshots were inspected in both palettes. Physical-device and accessibility qualification remain open; this is a focused improvement, not an award-quality claim.
